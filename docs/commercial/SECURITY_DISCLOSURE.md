# Reporting a security issue

If you believe you have found a security problem in TinyMRP, please report it
privately first. We would rather hear about it early and imperfectly than read
about it later.

## How to reach us

**Email:** [SECURITY CONTACT — must be set before publishing]
**PGP:** [optional; omit the line entirely rather than promising a key that
does not exist]

Please include what you did, what happened, and what you expected. A rough
description of a real problem is more useful than a polished report of a
theoretical one.

## What to expect

| Stage | Target |
| --- | --- |
| Acknowledgement | 3 working days |
| Initial assessment | 10 working days |
| Fix or documented decision | depends on severity; we will say which |

We will tell you what we decided and why, including when we decide not to act.

## Scope

In scope: the TinyMRP web application, its API, the SolidWorks add-in, and the
deployment scripts in this repository.

Out of scope: third-party services, denial of service through sheer volume, and
findings that require physical access to a customer's machine or an already
compromised account.

## Safe harbour

We will not pursue legal action against anyone who reports a problem in good
faith, tests only against their own installation, avoids accessing other
people's data, and gives us reasonable time before disclosing publicly.

If you are unsure whether something is in scope, ask before testing.

## Credit

We are glad to credit reporters by name in the changelog unless you prefer
otherwise. Say which when you report.

## A note on the licence

TinyMRP is public domain under The Unlicense, so anyone may run a copy we have
never seen. Reports about **your own** deployment are welcome, but we can only
fix the code — we cannot reach an installation we do not operate.
