# Project history and evidence (developers only)

Project history is intentionally concise and is not published in end-user Help.

Use these authoritative sources:

- [`../../CHANGELOG.md`](../../CHANGELOG.md) for release-level changes;
- Git commits and version tags for implementation history and rollback points;
- CI run artifacts and release assets for test, audit, SBOM and image evidence;
- [`../deployment/10-operations.md`](../deployment/10-operations.md) for current
  upgrade and rollback instructions;
- [`../development/MAINTENANCE.md`](../development/MAINTENANCE.md) for durable
  engineering rules.

Completed task transcripts, superseded commands, point-in-time scan counts and
incident narratives are not maintained as current-tree documentation. Git
history retains them when detailed archaeology is genuinely required.
